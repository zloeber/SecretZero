# SecretZero — Agent Memory

## Project Identity
Python CLI tool (`secretzero`) for declarative secrets lifecycle management. Secrets declared in `Secretfile.yml`, generated by pluggable generators, stored in pluggable targets (Vault, AWS, Azure, GitHub, etc.), tracked via a lockfile (`.gitsecrets.lock`).

## Key Files
- `src/secretzero/sync.py` — SyncEngine (core orchestrator)
- `src/secretzero/bundles/registry.py` — BundleRegistry singleton; all provider/generator/target dispatch
- `src/secretzero/models.py` — Pydantic v2 models (Secretfile, Secret, Provider, Target, etc.)
- `src/secretzero/config.py` — ConfigLoader (YAML parse + Jinja2 interpolation)
- `src/secretzero/lockfile.py` — Lockfile (SHA-256 hashes, provenance, rotation tracking)
- `src/secretzero/cli.py` — Click CLI entry point
- `.gitsecrets.lock` — default lockfile path

## Non-Negotiables
- Never store plaintext secret values (only SHA-256 hashes in lockfile)
- All provider/generator/target dispatch through BundleRegistry — no if/elif chains
- Pydantic v2: `model_dump()` not `.dict()`, `model_dump_json()` not `.json()`
- New providers/generators/targets register via `_get_bundle_manifest()` + `_register_builtin_bundles()`
- CLI output uses `rich.console.Console`, not bare `print()`
- Line length 100 (ruff + black)
